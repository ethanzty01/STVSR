# RSTT-S 渐进压缩实验报告：220k 训练、完整测试与 4K 部署

本轮已完成 **220,000 步训练**，得到 **286,140 参数、两帧输入、三帧输出、空间 ×4** 的 Tiny 模型。固定验证集均值 PSNR-Y 为 **29.329027 dB**，较原有 Tiny 的 **29.207041 dB** 提高 **0.121986 dB**。前八阶段 140k 时为 29.087807 dB；追加 80k 纯 GT 训练后提高 **0.241219 dB**。新旧两条路线均执行 220,000 次优化器更新，样本访问次数分别为 3.52M 与 3.36M。

报告更新于 2026-11-17。九个阶段的训练记录、权重衔接和优化器状态均已通过核验。完整四模型测试已完成：最终 Tiny 相对原有 Tiny 的 PSNR-Y 提升为 **Vid4 +0.0798 dB、Vimeo-Fast +0.3430 dB、Medium +0.1963 dB、Slow +0.1177 dB、REDS +0.1342 dB**，上述汇总 SSIM-Y 均提高。独立 4K 推理与实际视频测试均已完成；FP32 / AMP-FP16 的最大进程显存采样分别为 **5.85 / 4.48 GiB**，纯模型去重输出速度分别为 **8.08 / 9.69 fps**。

## 1. 实验设置与比较对象

| 比较对象 | 权重来源 | 作用 |
|---|---|---|
| RSTT-S 教师 | `checkpoints/RSTT-S/f96d4w4h24816Ushape0res_1690000.pth` | 原始结构与质量参照；前七阶段固定教师 |
| 原有 Tiny | `experiments/tiny_mixed_200k_b16/distilled_best.pth` | 先训练 20k，再混合 Vimeo/REDS 蒸馏训练 200k 的参照 |

环境为 **SRCHIP、RTX 5090、PyTorch 2.7.1+cu128、CUDA 12.8**。前八阶段和追加阶段使用 batch 16、BF16、`torch.compile(mode='reduce-overhead')`。模型选择使用 FP32 验证。

原始教师共有 4,485,275 个注册参数；其中第四个下采样卷积的 147,552 个参数未参与前向计算。渐进实现移除此注册项，载入原权重后的前向数值一致性已通过检查。最终 Tiny 的参数量较原始注册参数数目减少 **93.62%**。

## 2. 渐进修改与权重迁移

保留四级 U-Net、RGB 输入投影和编码器/解码器之间的跨注意力。原始教师的 `back_RBs=0`。每级深度由 4 减至 2 后保留一对普通窗口与移位窗口 block；decoder block 包含 self-attention、cross-attention 和 MLP。

| 阶段 | 修改 | 通道数 | 输入→输出帧数 | 每级 encoder / decoder 深度 | 参数量 | 更新步数 |
|---|---|---:|---|---|---:|---:|
| 01 | 重建头替换为直接 PixelShuffle ×4 | 96 | 4→7 | 4 / 4 | 3,786,984 | 10,000 |
| 02 | 两帧输入及时间/空间分离插值 | 96 | 2→3 | 4 / 4 | 3,669,384 | 20,000 |
| 03 | 编码器减深 | 96 | 2→3 | 2 / 4 | 3,062,292 | 10,000 |
| 04 | 解码器减深 | 96 | 2→3 | 2 / 2 | 2,133,564 | 10,000 |
| 05 | 通道裁剪至 64 | 64 | 2→3 | 2 / 2 | 984,572 | 20,000 |
| 06 | 通道裁剪至 48 | 48 | 2→3 | 2 / 2 | 579,036 | 20,000 |
| 07 | 通道裁剪至 32 | 32 | 2→3 | 2 / 2 | 286,140 | 30,000 |
| 08 | 纯 GT 微调 | 32 | 2→3 | 2 / 2 | 286,140 | 20,000 |
| 09 | 追加纯 GT 恢复 | 32 | 2→3 | 2 / 2 | 286,140 | 80,000 |

第一阶段保留原始 RGB 三线性插值基线。新头为 `Conv2d(C, 48, 3, padding=1) → PixelShuffle(4)`，前 2,000 步仅训练新头，其余 8,000 步同时训练主干。第二阶段改为时间线性插值 `align_corners=True`，空间逐帧双线性插值 `align_corners=False`，以两帧生成端点与中间帧。

时间注意力偏置按有符号时间偏移居中截取，并重新生成位置索引。深度裁剪比较保留 `[0,1]` 或 `[2,3]` 的立即验证表现：编码器选择 `[0,1]`，解码器选择 `[2,3]`。通道裁剪使用 32 个校准 batch 的投影与八级特征 RMS，结合投影权重 RMS，在最细的 16 个注意力分组内等量保留通道；残差路径采用一致的通道映射，MLP 中间通道独立筛选。

前七阶段使用下式训练：

`L = Charbonnier(GT) + 0.3 × 前阶段输出蒸馏 + 0.1 × 原始教师输出蒸馏 + 0.05 × 特征蒸馏`。

特征蒸馏对应 encoder/decoder 的四级输出。时间从四帧压缩为两帧时，教师 encoder 特征取 `j:j+2`，decoder 特征取 `2j:2j+3`；宽度改变时采用同一迁移通道索引。误差按教师各通道 RMS 归一化。第八、九阶段仅使用 GT Charbonnier。

头部学习率为 `1e-4`，主干为 `2e-5`；通道裁剪阶段全模型为 `5e-5`，各阶段余弦衰减至 `1e-6`。追加 GT 阶段全模型学习率重新从 `5e-5` 衰减至 `1e-6`。阶段衔接采用前阶段的验证最佳权重，初始迁移权重也参与最佳值选择。

## 3. 数据与计分协议

训练数据为 **64,484 个 Vimeo 片段和 24,628 个 REDS 窗口**。每个 batch 各取 8 个样本，以带替换采样实现数据集等权；HR patch 为 128×128，LR 为 32×32，包含随机裁剪、翻转、转置和时间顺序增强。数据拆分与随机种子记录在 `config.json`、`split_ids.json`，seed 为 2026。

数据预审核对了 Vimeo 的 train 64,484 / val 128 / test 7,815，片段 ID 与文件路径交叉均为 0。REDS 训练使用 262 段序列；验证序列为 `240/241/246/257`，测试序列为 `000/011/015/020`，序列、路径及窗口 ID 交叉均为 0。完整预审记录由评测流程写入 `../progressive_rstt_s_gt80k_b16/evaluation_preflight.json`。

每 2,000 步在固定 **Vimeo 128 + REDS 128** 验证片段上评估。预测与 GT 转为四舍五入的 RGB8，采用有限范围 Y 的 PSNR，逐帧算术平均，边缘裁剪为 0；模型选择分数为 Vimeo 与 REDS 的等权均值。四帧模型按相同 `pair_index` 选取对应三帧，与两帧模型使用一致的 GT 三帧。

最终完整测试统一在 `evaluate_progressive.py` 中比较四份权重：

- **Vimeo**：每片段计分七帧，Tiny 使用三个相邻两帧窗口，重叠端点保留首次输出；分别给出 Fast、Medium、Slow。LR 使用 PyTorch 抗锯齿 bicubic ×4 降采样并量化为 RGB8。
- **Vid4**：原始七帧窗口索引，每个全局帧计分一次；四段序列等权汇总。LR 处理同 Vimeo。
- **REDS**：七帧测试窗口的中间三帧，LR 保留浮点值；重叠窗口中的帧观察分别计分。
- 共同输出 FP32 推理的 PSNR-RGB、PSNR-Y、SSIM-Y，并拆分端点与插值中间帧。图表中的论文指标与本地重新评估值按来源分别标注。

## 4. 实际训练预算

“更新次数”统计优化器执行步数；“样本访问”统计优化器训练 batch 中抽取的片段次数，包含重复抽样。验证与通道校准的前向访问单独记录。已有 RSTT-S 权重的预训练成本单列为共有教师来源。

| 路线 | 更新预算 | 样本访问计算 | 总样本访问 | Vimeo / REDS 访问 |
|---|---|---|---:|---|
| 原有 Tiny | 20k + 200k = **220k** | 20k×8 + 200k×16 | **3,360,000** | 1,760,000 / 1,600,000 |
| 渐进首轮，已完成 | **140k** | 140k×16 | **2,240,000** | 1,120,000 / 1,120,000 |
| 渐进完整路线，已完成 | 140k + 80k = **220k** | 220k×16 | **3,520,000** | 1,760,000 / 1,760,000 |

两条完整路线均为 **220k 更新**；新路线的样本访问多 **160,000 次，约 4.76%**，增加部分来自 REDS。原有 Tiny 的前 20k 使用 Vimeo、batch 8；其后 200k 才使用等权 Vimeo/REDS。

结构也随训练时间变化：原有路线的全部 220k 更新训练最终 Tiny 结构；新路线在第 07 阶段才到达 32 通道最终结构，首轮包含 **50k** 次该结构更新，追加完成后累计 **130k** 次。此前阶段的较大模型通过迁移向后提供初始化。这些预算差异与训练方法共同构成本次比较条件。

原有 Tiny 执行完整 220k 更新，最佳权重来自累计 **218k**；渐进路线同样执行完整 220k 更新，最佳权重来自累计 **214k**，对应第九阶段局部 **74k**。后文将“完整执行预算”与“选中权重所在步数”分别报告。

**高运动片段的插帧是本次改善最明显的位置。** Vimeo-Fast 中间帧从 **28.481631 / 0.836713** 提高到 **29.217677 / 0.851617**，提升 **0.736046 dB**；同组端点提升 **0.048290 dB**。Medium、Slow 与 REDS 的中间帧提升也分别高于各自的端点提升。这个分布支持本次完整组合训练对运动插值的改善。

Vid4 四段序列的全帧 PSNR-Y 都提高，幅度从 foliage 的 **+0.014167 dB** 到 walk 的 **+0.162027 dB**。细分结果中，foliage 中间帧相对原有 Tiny 下降 **0.027742 dB**、SSIM-Y 下降 **0.000376**；其余三段中间帧提高，四序列等权中间帧均值为 **+0.065556 dB**。

与教师的质量差距仍较明显：Vimeo 全集为 **2.766367 dB**，Fast 中间帧为 **4.153400 dB**（Tiny **29.217677**，教师 **33.371077**）。结构层面，四帧改为两帧减少了可用于遮挡和运动推断的上下文，96→32 通道与每级 4→2 block 同时缩减了表示容量，直接重建头也缩短了高分辨率重建过程。Fast 中间帧较大的剩余差距与运动插值仍是主要难点这一观察一致。

当前测试收益针对本次“**教师初始化迁移 → 渐进裁剪与蒸馏恢复 → 追加纯 GT 训练**”的组合路径。第 4 节同时披露相同 220k 更新下的 **3.52M / 3.36M** 样本访问差异，以及最终结构接受更新次数的差异。报告据此描述该组合训练获得的结果，独立模块贡献保留给进一步的平行实验。

## 9. 独立部署与峰值显存

测试条件为 **RTX 5090、单独加载最终 Tiny、batch 1、两帧 960×540 输入、空间 ×4 和时间 ×2，输出 3840×2160**。FP32 与 AMP-FP16 各自使用新进程，分别执行推理基准和实际视频转换。基准覆盖冷启动、两次预热、十次稳定成对前向、六帧输入的有界流式处理；实际视频覆盖六十帧输入的完整解码、推理、传回 CPU 和编码过程。所有进程使用相同最终权重，部署汇总核验通过，见 [deployment_summary.json](../progressive_rstt_s_gt80k_b16/deployment_summary.json)。

下表取独立推理基准与实际视频两次测量中的**最大观察峰值**。allocated 为 PyTorch 活跃张量分配的高水位，reserved 为 CUDA 分配器预留的高水位；进程显存通过 nvidia-smi 每 0.1 秒采样，包含分配器与 CUDA 上下文等占用。GiB 为 MiB 除以 1024。

| 精度 | 张量峰值 allocated | 分配器峰值 reserved | 进程显存采样峰值 |
|---|---:|---:|---:|
| FP32 | **3,637.766 MiB / 3.553 GiB** | **5,374 MiB / 5.248 GiB** | **5,988 MiB / 5.848 GiB** |
| AMP-FP16 | **2,946.120 MiB / 2.877 GiB** | **3,970 MiB / 3.877 GiB** | **4,586 MiB / 4.479 GiB** |

稳定前向使用 CUDA event 计时；连续流每对输入新增两帧，因此模型吞吐为 2 / 每对耗时。各阶段原始峰值和形状记录分别见 [FP32 基准](../progressive_rstt_s_gt80k_b16/deployment_fp32.json)与 [AMP 基准](../progressive_rstt_s_gt80k_b16/deployment_amp_fp16.json)。

| 精度 | 纯模型每对耗时 | 纯模型去重输出速度 | 含传输和 CPU RGB8 转换的流式速度 | 一秒样例完整转换耗时 | 含视频编解码的输出速度 |
|---|---:|---:|---:|---:|---:|
| FP32 | **247.621 ms** | **8.077 fps** | **5.331 fps** | **28.262 s** | **4.246 fps** |
| AMP-FP16 | **206.417 ms** | **9.689 fps** | **6.048 fps** | **25.712 s** | **4.667 fps** |

实际视频输入使用 REDS 测试序列 000 的前 60 帧，缩小到 960×540 并设定 60fps；来源见 [源视频记录](../tiny_mixed_200k_b16/demo_input_960x540_60fps.source.json)。流式模型生成 119 帧，最后在 CPU 保持末帧一次，得到 **120 帧、3840×2160、120fps、时长 1 秒**的输出。两份文件均重新完整解码，核对了全部 120 帧、尺寸和帧率。编码采用 OpenCV FFmpeg CPU 的 mp4v。

- [FP32 4K120 视频](../progressive_rstt_s_gt80k_b16/demo_4k120_fp32.mp4)与[转换记录](../progressive_rstt_s_gt80k_b16/demo_4k120_fp32.json)。
- [AMP-FP16 4K120 视频](../progressive_rstt_s_gt80k_b16/demo_4k120_amp_fp16.mp4)与[转换记录](../progressive_rstt_s_gt80k_b16/demo_4k120_amp_fp16.json)。

**120fps 表示生成文件的播放时间轴；当前实现的实际处理速度见上表。** 持续实时输出 120fps 对应每对输入在 16.67ms 内完成；本轮测得 247.62ms / 206.42ms，后续速度优化仍有较大空间。

主要存储内容包括：模型权重和位置索引缓冲、当前输入两帧、四级 encoder 特征、当前 decoder query、注意力 Q/K/V 与概率矩阵、移位窗口 mask、MLP 中间激活、重建头输出及返回三帧张量、卷积工作区和 CUDA 分配器缓存。三帧拼接返回时，各帧结果与拼接张量存在重叠生存期。模型前向期间的峰值由这些张量的同时存活情况决定，上表为实际测量值。

下表为 CPU 核对的 **FP32 静态张量容量**，每项对应特定存储对象及其生存期，单位 MiB=`2^20` bytes；设备峰值由上表的独立测量给出。逐层尺寸和容量见 [architecture_deployment_notes.json](architecture_deployment_notes.json)。

| 存储对象 | 静态容量 MiB |
|---|---:|
| 286,140 个 FP32 权重 | 1.092 |
| int64 位置索引缓冲 | 0.297 |
| 两帧 LR RGB 输入 | 11.865 |
| 四级 encoder 输出合计 | 169.336 |
| 最高分辨率 decoder 的单张 self-attention 分数或概率张量 | 573.750 |
| 最高分辨率 decoder 的单张 cross-attention 分数或概率张量 | 382.500 |
| 最高分辨率 decoder 的 self/cross mask 合计 | 478.125 |
| 最高分辨率 decoder 的 MLP 中间特征 | 382.500 |
| 返回前，逐帧输出列表与新拼接三帧张量同时存活 | 569.531 |

这些容量说明注意力临时量与输出缓存占据主要存储，权重本身约 1.09 MiB。AMP 使用 FP32 权重与 autocast；本实现的 RGB 插值基线和最终返回输出仍为 FP32，部分 mask、位置偏置及其参与的注意力计算也保留 FP32，因此本轮 AMP 的显存降幅约为张量峰值的 **19.0%**。逐模块实际 shape 与 dtype 记录在两份基准文件的 stage_trace 中。

长视频按相邻两帧滑动处理，释放已消费的输出并保留下一对所需的端点。GPU 存储随当前帧对和模型中间量变化，六十帧视频逐对送入。实际视频的图像解码、RGB8 帧缓存和编码在 CPU 进行，整段处理的 GPU 峰值已纳入上表。

训练阶段显存另见各阶段 `summary.json`：最大记录为第一阶段 allocated **4,975.21 MiB**、reserved **6,090 MiB**，该范围包含训练与验证，使用 HR128 patch 和教师。上述 4K 部署测量采用独立进程，仅加载最终 Tiny。
